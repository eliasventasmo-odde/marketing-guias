🛡️ Por qué existen los permisos

El fundamento de seguridad antes de entender los modos

💡
La realidad: Claude Code no es solo un chat. Tiene acceso real a tu ordenador — puede leer, crear, editar y borrar archivos. También puede ejecutar comandos en el sistema. Eso es poder real que necesita control real.
🎯
La analogía perfecta: Es como darle a un empleado llave de toda la oficina. Es muy útil para trabajar — pero necesitas definir a qué cuartos puede entrar, qué cajones puede abrir y qué nunca debe tocar. Los permisos son esas reglas escritas.
Sin permisos configuradosCon permisos configurados
Claude Code pregunta por todo, todo el tiempoSolo pregunta lo que tú decides que debe preguntar
Puede intentar ejecutar cualquier comandoCiertos comandos están bloqueados para siempre
Puede leer cualquier archivo incluyendo credencialesLos archivos sensibles están en la lista deny
Si se equivoca no hay red de seguridad/rewind permite deshacer cualquier cambio

🔄 Los 5 modos de permisos

Cada modo define cuánto control tienes sobre las acciones de Claude Code

default Tu modo actual ✓
✓ Lee archivos sin preguntar
⚡ Pregunta antes de editar
⚡ Pregunta antes de ejecutar Bash
Úsalo para: Trabajo diario con clientes reales. El más seguro.
acceptEdits
✓ Lee archivos sin preguntar
✓ Edita archivos sin preguntar
⚡ Pregunta antes de ejecutar Bash
Úsalo para: Cuando tienes que editar muchos archivos de golpe — como rellenar los 12 briefs de clientes.
plan
✓ Lee y analiza sin preguntar
❌ No puede editar nada
❌ No puede ejecutar comandos
Úsalo para: Revisar proyectos de clientes sin riesgo de cambios accidentales.
bypassPermissions
✓ Todo sin preguntar nunca
⚠️ Sin ninguna protección
SOLO para: Servidores Docker aislados. NUNCA en tu ordenador personal con datos de clientes.
dontAsk
✓ Solo lo que está en allow
❌ Todo lo demás denegado
Úsalo para: Cuando quieres control máximo — solo ejecuta lo que tú hayas aprobado explícitamente.

Cómo cambiar de modo

# Durante la sesión (sin cerrar Claude Code): Shift+Tab → cicla entre modos # Al arrancar con un modo específico: claude --permission-mode acceptEdits claude --permission-mode plan # Como modo por defecto en settings.json: "permissions": { "defaultMode": "acceptEdits" }

👁️ Panel /permissions

Tu centro de control visual para gestionar todas las reglas

💡
¿Qué es /permissions? Es un panel visual dentro de Claude Code que muestra todas las reglas activas organizadas en 4 pestañas. Puedes añadir, ver y gestionar permisos sin tocar el settings.json.
PestañaQué muestraTu contenido actual
Allow Comandos que ejecutan sin preguntar nunca git status, git diff, git log, mkdir, ls, dir
Ask Comandos que siempre piden confirmación Todo lo no incluido en allow o deny
Deny Comandos bloqueados para siempre rm -rf, sudo, leer archivos .env
Workspace Carpetas de trabajo autorizadas C:\Users\elias\claudecode-practicas
⚠️
Las reglas duplicadas son normales. Cuando veas la misma regla dos veces en Allow (por ejemplo Bash(mkdir *)), es porque está tanto en el settings global como en el settings de proyecto. No afecta al funcionamiento — simplemente se aplica una vez.

✅ Reglas Allow y Deny

El sistema de reglas permanentes que configuras una vez y funcionan siempre

Tus reglas actuales

TipoReglaQué significaPor qué la tienes
ALLOWBash(git status)Ver estado del repositorioFrecuente y seguro — sin riesgo
ALLOWBash(git diff *)Ver diferencias en archivosSolo lectura — no modifica nada
ALLOWBash(mkdir *)Crear carpetasNecesario para crear estructuras de clientes
ALLOWBash(ls *)Listar archivosSolo lectura — necesario para navegar
DENYBash(rm -rf *)Borrar carpetas completasIrreversible — demasiado peligroso
DENYBash(sudo *)Comandos de administradorAcceso total al sistema — bloqueado
DENYRead(*.env)Leer archivos de credencialesContienen contraseñas y API keys

Cómo añadir reglas nuevas

# Opción 1 — Desde el panel /permissions: /permissions → pestaña Allow → "Add a new rule…" # Opción 2 — Desde lenguaje natural: Añade al settings.json global en deny: Bash(git push *) # Opción 3 — Editando el settings.json directamente: "permissions": { "deny": [ "Bash(rm -rf *)", "Bash(git push *)" ← nueva regla añadida ] }

↩️ Comando /rewind — Tu red de seguridad

El comando más importante cuando algo no sale como esperabas

✅
¿Qué hace /rewind? Muestra el historial completo de cambios que hizo Claude Code en la sesión actual. Puedes seleccionar cualquier punto anterior y restaurar el código y la conversación a ese estado exacto. Es como Ctrl+Z pero para toda una sesión de trabajo.

Cómo funciona en la práctica

# 1. Escribe /rewind en el prompt: /rewind # 2. Verás el historial de la sesión: Añade una línea al archivo brief.md... brief.md +2 -0 ← lo que cambió > (current) ← donde estás ahora # 3. Subes con flecha arriba hasta el punto que quieres # 4. Pulsas Enter y eliges: 1. Restore code and conversation ← restaura todo 2. Restore conversation ← solo el chat 3. Restore code ← solo los archivos
⚠️
Limitación importante: /rewind NO afecta a archivos editados manualmente por ti o mediante comandos Bash directos. Solo deshace los cambios que hizo Claude Code a través de sus herramientas Write y Edit.

🏢 Beneficio real para MarketingMo

Cómo aplicar el sistema de permisos en tu trabajo diario con 12 clientes

📋
Flujo 1 — Rellenar briefs de clientes (modo acceptEdits)
Cuando necesitas actualizar muchos archivos de clientes sin interrupciones

Arrancar con acceptEdits cuando vas a hacer una sesión intensiva de trabajo con archivos de clientes. Claude Code edita sin preguntar — tú revisas al final con /rewind si algo no está bien.

claude --permission-mode acceptEdits → Rellena el brief de Eli Nails con toda la información del cliente → Actualiza el calendario de contenido de Diva Estudio para abril → Genera el informe ADM de Pastelería Rico del mes de marzo ← Al terminar: /rewind para revisar todos los cambios de golpe
🔍
Flujo 2 — Auditoría de cliente sin riesgo (modo plan)
Cuando el Agente ACI analiza un prospecto sin poder modificar nada

Usar el modo plan cuando quieres que Claude Code analice la información de un cliente potencial sin riesgo de tocar archivos de clientes activos.

claude --permission-mode plan → Analiza todos los archivos del prospecto Clínica Dental Pérez → Compara con los benchmarks del sector salud → Dame un informe de qué necesita mejorar en su presencia digital ← Claude analiza y reporta — no puede modificar nada
🔐
Flujo 3 — Proteger datos de clientes con reglas Deny
Reglas recomendadas para añadir a tu settings.json para MarketingMo

Reglas adicionales que deberías añadir cuando tu carpeta de prácticas evolucione a producción real con datos reales de clientes.

"deny": [ "Bash(rm -rf *)", ← Ya tienes esta "Bash(sudo *)", ← Ya tienes esta "Read(*.env)", ← Ya tienes esta "Read(*contraseña*)", ← Añadir: archivos de contraseñas "Read(*password*)", ← Añadir: archivos de passwords "Bash(git push *)" ← Añadir: evitar push accidentales ]
⚡
Flujo 4 — Deshacer con /rewind cuando algo falla
Tu protocolo de emergencia cuando Claude Code hace algo inesperado

Si Claude Code modifica un archivo de cliente de forma incorrecta — por ejemplo escribe en el brief de Eli Nails información de otro cliente — usa /rewind inmediatamente.

Situación: Claude Code mezcló datos de dos clientes en un brief Solución inmediata: /rewind → Selecciona el punto antes del error → "Restore code and conversation" → Todo vuelve al estado anterior en segundos

🚫 Qué NO hacer con los permisos

Errores que comprometen la seguridad de tu agencia y los datos de tus clientes

❌
NUNCA uses bypassPermissions en tu ordenador con datos reales de clientes. Este modo deshabilita todas las protecciones. Si Claude Code comete un error en este modo, no hay red de seguridad. Solo existe para entornos Docker completamente aislados.
❌
NUNCA quites rm -rf del deny. Este comando puede borrar la carpeta entera de un cliente en un segundo de forma irreversible. No hay /rewind que lo recupere porque es un comando Bash directo.
❌
NUNCA aceptes "Yes, allow all edits during this session" sin pensarlo. Esta opción desactiva todas las confirmaciones para el resto de la sesión. Si Claude Code malinterpreta una instrucción puede modificar archivos de múltiples clientes sin que te enteres.
⚠️
Cuidado con el modo acceptEdits cuando trabajas con varios clientes a la vez. Si tienes briefs de Eli Nails y Diva Estudio abiertos en el contexto y usas acceptEdits, Claude Code puede editar ambos sin preguntar. Trabaja cliente por cliente en este modo.
⚠️
/rewind tiene límites. Solo deshace cambios de la sesión actual. Si cierras Claude Code y vuelves a abrirlo, el historial de /rewind se resetea. Para proyectos importantes usa git para tener un historial permanente de cambios.
