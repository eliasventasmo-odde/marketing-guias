🤖 Qué son los agentes y subagentes

La diferencia entre Claude Code respondiendo y Claude Code delegando

💡
Definición simple: Un agente es una instancia especializada de Claude con su propio sistema de instrucciones, su propio modelo y su propia memoria. Cuando Claude Code delega una tarea a un agente, ese agente trabaja en su propio contexto — no interfiere con la conversación principal ni con otros agentes.

La analogía de la agencia

🏢
Sin agentes: Eres tú solo haciendo todo — escribes el brief, analizas las métricas, haces la auditoría, generas el calendario. Un trabajo tras otro. Con agentes: tienes un equipo especializado. Le dices al equipo qué necesitas y cada especialista hace su parte simultáneamente. Tú solo revisas y apruebas.
CaracterísticaClaude Code soloClaude Code con agentes
Tareas simultáneasUna a la vezMúltiples en paralelo
ContextoUn solo contexto compartidoCada agente tiene el suyo
EspecializaciónGeneralistaCada agente es experto en su área
VelocidadTareas secuenciales3 agentes = 3x más rápido
MemoriaSolo la sesión activaMemoria persistente por proyecto

Tienes dos herramientas — aquí está cuándo usar cada una

Cómo se activanTú los ejecutas manualmenteClaude Code los delega automáticamente
Para qué sirvenGenerar documentos con plantilla fijaRazonar, decidir y ejecutar tareas complejas
ParalelismoNo — uno a la vezSí — múltiples simultáneos
MemoriaSin memoria entre ejecucionesMemoria persistente del proyecto
Ejemplo MarketingMo/brief-cliente eli-nails → plantilla vacía@bac-marketingmo → analiza, decide y genera
✅
La regla: Usa slash commands para generar documentos con estructura fija. Usa agentes para tareas que requieren razonamiento, análisis o trabajo en paralelo. Los dos conviven — no se sustituyen.

⚡ Ejecución en paralelo — cómo funciona

El momento donde Claude Code se convierte en un equipo real

🌿 Worktrees — aislamiento total

El siguiente nivel de paralelismo — cada tarea en su propio espacio

💡
Definición: Un worktree es una copia de trabajo aislada de tu repositorio git con su propia rama y sus propios archivos, pero compartiendo el mismo historial. Cada terminal con worktree es un Claude Code completamente independiente que no puede interferir con los demás.

La diferencia entre agentes en paralelo y worktrees

AspectoAgentes en paralelo (lo que hiciste)Worktrees (nivel siguiente)
AislamientoAgentes en el mismo espacio de trabajoCada tarea en su propia carpeta
Conflictos de archivosPosibles si dos agentes tocan el mismo archivoImposibles — espacios completamente separados
Control de cambiosTodos los cambios en la rama actualCada worktree en su propia rama git
FusiónAutomáticaTú decides qué cambios conservar

Cómo usarías worktrees en MarketingMo

# Cuándo usar worktrees para MarketingMo: ✅ Generar varios calendarios de clientes distintos a la vez ✅ ACI + ADM + BAC con aislamiento total de archivos ✅ Preparar informes de fin de mes para todos los clientes simultáneamente # Cuándo NO usar worktrees: ❌ El calendario de un cliente depende del brief que estás escribiendo ahora ❌ Tareas que duran menos de 5 minutos — overhead innecesario ❌ Cambios que necesitan coordinarse entre sí

Patrón 2 — Cierre de mes automatizado

Luego usa @bac-marketingmo para generar el calendario del mes siguiente y crear la base de datos en Notion con el formato estándar.

Patrón 3 — Onboarding de cliente nuevo

# Cuando cierra un contrato nuevo: @aci-auditoria-cliente-inicial genera la auditoría completa de [nuevo-cliente], registra el baseline Día 0 y crea su página en Notion. Luego /brief-cliente [nuevo-cliente] para el brief de onboarding. Finalmente @bac-marketingmo genera el primer calendario del mes.

Patrón 4 — Combinación con Skills

# Análisis competitivo profundo para prospecto: @competitive-analysis analiza la competencia de [prospecto] en el sector [X] y @aci-auditoria-cliente-inicial genera la auditoría digital completa. Combina ambos análisis en una propuesta comercial para [prospecto].
