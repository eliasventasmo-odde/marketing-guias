⌨️ Qué es un slash command personalizado

La diferencia entre los comandos del sistema y los que tú creas

💡
Definición simple: Un slash command personalizado es un archivo de texto que tú creas con instrucciones para Claude Code. Cuando escribes /nombre-comando argumento, Claude Code lee ese archivo, reemplaza el argumento donde corresponde y ejecuta las instrucciones automáticamente.
TipoEjemplosQuién los creaDónde viven
Comandos del sistema/help, /clear, /status, /exit, /rewindAnthropic — vienen con Claude CodeInternos — no puedes verlos
Comandos preinstalados/batch, /claude-api, /debugAnthropic — extras opcionalesSistema
Comandos personalizados Los tuyos ✓/brief-cliente, /informe-adm, /auditoria-aciTú — adaptados a MarketingMo.claude/commands/
🎯
La analogía perfecta: Es como programar una macro en Excel. En vez de hacer los mismos pasos cada vez, creas un botón que los ejecuta todos de golpe. Tus slash commands son esos botones — uno por cada proceso repetitivo de tu agencia.

🏗️ Estructura técnica de un comando

Cómo está construido por dentro cada archivo de comando

Cada comando es un archivo .md con dos partes: el frontmatter (configuración) y el cuerpo (instrucciones).

─── PARTE 1: FRONTMATTER (configuración entre --- y ---) ───
---
description: Genera el brief completo usando el Sistema B.A.C.
argument-hint: [nombre del cliente]
---
 
─── PARTE 2: CUERPO (instrucciones para Claude Code) ───
Eres el Agente B.A.C. de MarketingMo.
Crea el archivo clientes/$ARGUMENTS/brief.md
con la plantilla del Sistema B.A.C...
ElementoQué esEjemplo
descriptionTexto que aparece en /help junto al nombre del comando"Genera el brief completo del Sistema B.A.C."
argument-hintTexto de ayuda que muestra qué argumento se espera"[nombre del cliente]"
$ARGUMENTSSe reemplaza automáticamente por lo que escribes después del comando/brief-cliente nobleza → $ARGUMENTS = "nobleza"
Cuerpo del archivoLas instrucciones completas que Claude Code ejecutaráToda la plantilla del brief, el informe o la auditoría
✅
$ARGUMENTS es la clave. Cada vez que aparece $ARGUMENTS en el archivo del comando, Claude Code lo reemplaza por el texto que tú escribiste después del slash command. Así /brief-cliente nobleza crea el archivo en clientes/nobleza/ automáticamente.

Cómo conectar Metricool con el informe

🔗
El flujo con Metricool funciona así: Metricool no tiene MCP server oficial aún, pero Claude Code puede leer sus exportaciones directamente. Este es el flujo correcto hoy.
# Paso 1 — Genera el informe base: /informe-adm diva-estudio # Paso 2 — Exporta desde Metricool: En Metricool → Informes → Exportar PDF o CSV → guardar en: clientes/diva-estudio/metricool-marzo2026.pdf # Paso 3 — Pídele que rellene el informe con esos datos: analiza el informe Metricool de diva-estudio y rellena el informe-adm.md con los datos reales # Resultado: → Claude Code lee el PDF/CSV de Metricool → Extrae todas las métricas → Rellena las tablas del informe automáticamente → Informe mensual completo en minutos, no en horas
✅

➕ Cómo crear comandos nuevos en el futuro

El proceso exacto para crear cualquier slash command propio desde cero

📝 Proceso paso a paso para crear un comando nuevo
1
Abre Claude Code en tu carpeta de trabajo y escribe en lenguaje natural la instrucción completa.
2
Usa este formato base:
"Crea el archivo .claude/commands/[nombre-comando].md con este contenido: [frontmatter + instrucciones]"
3
El frontmatter mínimo que necesita cualquier comando:
description: qué hace el comando (aparece en /help)
argument-hint: qué parámetro espera el usuario
4
Usa $ARGUMENTS en el cuerpo donde quieras que aparezca el nombre del cliente, prospecto o lo que corresponda.
5
Cierra Claude Code y vuelve a abrirlo — /exit → cd carpeta → claude. Necesita reiniciarse para detectar el nuevo comando.
6
Prueba el comando con un nombre de prueba: /[nombre-comando] prueba y verifica que el archivo se crea correctamente.

Plantilla base para cualquier comando nuevo

# Escribe esto en el prompt > de Claude Code: Crea el archivo .claude/commands/nombre-comando.md con este contenido: --- description: [Qué hace este comando — aparece en /help] argument-hint: [nombre del cliente/prospecto/proyecto] --- Eres el Agente [BAC/ADM/ACI] de MarketingMo. Crea el archivo clientes/$ARGUMENTS/[nombre-archivo].md con la siguiente estructura: # [Aquí va toda la plantilla del documento] # Agencia: MarketingMo · @marketingMo · nietomonica.com # Responsable: Mónico Nieto
⚠️
Recuerda siempre: Después de crear un comando nuevo hay que cerrar y reabrir Claude Code para que lo detecte. Si escribes el comando y aparece "Unknown skill", es porque no has reiniciado todavía.

🚫 Qué NO hacer con los slash commands

Errores que pueden romper tus comandos o generar resultados incorrectos

❌
NUNCA uses espacios en el nombre del archivo del comando. El archivo debe llamarse brief-cliente.md con guión, no brief cliente.md con espacio. Los espacios rompen la detección del comando.
❌
NUNCA olvides reiniciar Claude Code después de crear un nuevo comando. Si escribes el comando y aparece "Unknown skill", es porque Claude Code no lo ha detectado aún. Siempre: /exit → cd carpeta → claude.
❌
NUNCA incluyas credenciales o contraseñas en las plantillas de los comandos. Los archivos .md de los comandos son texto plano visible. Si alguien accede a tu carpeta puede leerlos. Las credenciales van en archivos .env separados.
⚠️
Cuidado con los nombres de clientes con espacios o caracteres especiales. Cuando uses /brief-cliente Eli Nails con espacio, $ARGUMENTS tomará solo "Eli". Lo correcto es usar guiones: /brief-cliente eli-nails.
⚠️
Si modificas un comando existente, los cambios aplican en la siguiente ejecución. No necesitas reiniciar Claude Code para que tome los cambios en un comando ya creado — solo para comandos nuevos que aún no ha detectado.
