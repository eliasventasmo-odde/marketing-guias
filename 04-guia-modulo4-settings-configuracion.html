⚙️ Settings.json vs CLAUDE.md

La diferencia fundamental entre los dos archivos de configuración

💡
La distinción clave: El CLAUDE.md es la memoria del proyecto — le dice a Claude Code quién eres y cómo trabajas. El settings.json es la configuración del sistema — controla cómo se comporta Claude Code técnicamente: qué modelo usar, qué permisos tiene, en qué idioma responde.
AspectoCLAUDE.mdsettings.json
¿Qué contiene?Instrucciones en lenguaje natural, contexto del proyecto, clientes, agentesConfiguración técnica: modelo, idioma, permisos, variables de entorno
¿Formato?Markdown — texto con formato simpleJSON — estructura de datos técnica
¿Quién lo lee?Claude Code lo carga como contexto de conversaciónClaude Code lo usa para configurar su comportamiento
¿Cuándo aplica?Desde el primer mensaje de cada sesiónDesde el arranque, antes de cualquier mensaje
¿Puedes editarlo?Sí — en lenguaje natural o VS CodeSí — en lenguaje natural o Notepad/VS Code
🎯
Analogía definitiva: Si Claude Code fuera un empleado, el CLAUDE.md sería su manual de instrucciones del trabajo y el settings.json sería su contrato laboral — las condiciones generales que aplican siempre, en cualquier proyecto.

🔐 Sistema de permisos

Qué puede hacer Claude Code automáticamente y qué está bloqueado

🛡️
¿Qué es el sistema de permisos? Claude Code siempre te pide confirmación antes de ejecutar comandos en tu ordenador. Con los permisos puedes definir qué comandos se ejecutan automáticamente sin preguntar (allow) y cuáles están bloqueados para siempre (deny).

Tus permisos actuales

✅ PERMITIDOS — Ejecutan sin preguntar
Bash(git status)
Bash(git diff *)
Bash(git log *)
Bash(mkdir *)
Bash(ls *)
Bash(dir *)
Comandos de solo lectura y creación de carpetas — seguros y frecuentes.
❌ BLOQUEADOS — Nunca se ejecutan
Bash(rm -rf *)
Bash(sudo *)
Read(*.env)
Comandos destructivos y acceso a credenciales — bloqueados por seguridad en todos los proyectos.

Sintaxis de reglas de permisos

# Formato: Herramienta(patrón) # Herramientas disponibles: Bash(comando) # Comandos de terminal Read(ruta) # Leer archivos Write(ruta) # Escribir archivos Edit(ruta) # Editar archivos # El * significa "cualquier cosa": "Bash(git *)" # Cualquier comando git "Write(clientes/**)" # Escribir en clientes/ y subcarpetas "Read(*.env)" # Leer cualquier archivo .env # Ejemplos prácticos para MarketingMo: "Write(clientes/**)" # ✅ Libre para escribir en carpetas de clientes "Bash(rm -rf *)" # ❌ Bloqueado — borrado masivo peligroso

Los 3 modos de permisos

ModoComportamientoCuándo usarlo
default Tu modo actualPide confirmación para cada operación potencialmente peligrosaUso diario normal — el más seguro
acceptEditsAprueba automáticamente modificaciones de archivos. Bash sigue preguntandoCuando editas muchos archivos seguidos
planSolo lectura — no puede modificar nada, solo analizar y planificarPara revisar proyectos sin riesgo de cambios

🔄 Actualizaciones del sistema

Qué puede actualizar Claude Code y cómo pedírselo

✅ Claude Code
claude update
Se actualiza solo automáticamente con el canal "stable" configurado. También puedes pedírselo directamente.
✅ npm
npm install -g npm@latest
Claude Code puede ejecutar este comando sin problema. Solo pídele "actualiza npm".
⚠️ Node.js
Descarga manual en nodejs.org
Puede guiarte paso a paso pero en Windows la instalación requiere que tú ejecutes el instalador.
⚠️ Git
git update-git-for-windows
Puede ejecutar el comando pero Windows puede requerir confirmación de administrador.
❌ VS Code
Automático desde VS Code
VS Code se actualiza solo desde su propia interfaz. Claude Code no puede tocarlo.

Cómo pedir actualizaciones desde Claude Code

# Actualizar Claude Code: actualízate a la última versión # O desde PowerShell directamente: claude update # Ver la versión actual: claude --version # Verificar si hay actualizaciones disponibles: ¿Tienes actualizaciones pendientes? # Actualizar npm: actualiza npm a la última versión
✅
Tu configuración ya está en modo "stable". Esto significa que Claude Code se actualiza automáticamente cuando hay una versión estable nueva — sin que tengas que hacer nada. Solo las versiones beta (inestables) se saltan.

🚫 Qué NO hacer con el settings.json

Errores que pueden comprometer tu seguridad o romper la configuración

❌
NUNCA añadas contraseñas o API keys en la sección "env" del settings.json. Aunque parece un lugar seguro para variables de entorno, el settings.json puede ser leído por Claude Code y enviado como contexto. Usa archivos .env separados para credenciales y asegúrate de que están en el deny list.
❌
NUNCA quites el bloqueo de rm -rf * del deny. Este comando borra carpetas enteras de forma irreversible. Aunque creas que lo necesitas para alguna tarea, es más seguro ejecutarlo manualmente tú mismo que dárselo a Claude Code.
❌
NUNCA cambies el defaultMode a "bypassPermissions". Este modo omite todos los avisos de seguridad. Es equivalente al flag --dangerously-skip-permissions. Solo existe para entornos Docker completamente aislados.
⚠️
Cuidado con el JSON mal formado. Si el settings.json tiene un error de sintaxis (una coma de más, una llave que falta), Claude Code no arrancará correctamente. Si algo falla después de editar el settings, pídele a Claude Code que "verifique y corrija el settings.json".
⚠️
No cambies el canal de actualizaciones a "latest" sin razón. El canal "latest" incluye versiones beta que pueden tener errores. El canal "stable" que tienes ahora es siempre la opción más segura para trabajo de producción.
