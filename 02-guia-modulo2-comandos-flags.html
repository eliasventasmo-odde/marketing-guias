⚑ ¿Qué es un Flag?

El concepto base antes de aprender los comandos

💡
Definición simple: Un flag (bandera en inglés) es una instrucción adicional que le añades al comando claude cuando lo abres desde PowerShell. Modifica cómo se comporta antes de que empiece a trabajar. Es como darle configuraciones especiales al arrancar.

Estructura básica

# Estructura: claude [flag] "tu instrucción" # Ejemplos: claude # Sin flags — abre el chat normal claude -p "analiza este archivo" # Con flag -p — ejecuta y sale claude --model opus # Con flag --model — usa Opus claude -p -s "eres experto" "tarea" # Varios flags combinados
✅
Los flags se pueden combinar. Puedes usar -p con -s al mismo tiempo para ejecutar una tarea con un rol específico sin abrir el chat interactivo. Eso es la base de la automatización.

⚡ Flag -p (--print)

El flag más importante para automatización

-p --print Muy usado

Qué hace: Ejecuta una tarea en modo no interactivo (Non-Interactive Mode = modo sin conversación). Claude Code procesa la instrucción, devuelve el resultado y sale automáticamente. No abre el chat.

¿Cuándo usarlo? Para tareas rápidas sin conversación, para automatizaciones en n8n, para scripts que se ejecutan solos sin intervención humana.

Ejemplos prácticos

# Pregunta rápida sobre tu carpeta: claude -p "Dime qué archivos hay en esta carpeta" # Leer el contenido de un archivo: claude -p "Lee el archivo prueba.txt y dime su contenido" # Crear contenido y guardarlo: claude -p "Dame 5 ideas de posts para Instagram de una clínica dental" # Para MarketingMo — análisis de cliente: claude -p "Analiza el archivo brief-cliente.md y dame un resumen ejecutivo"

❌ Sin flag -p

  • Abre el chat interactivo
  • Tienes que escribir la instrucción
  • Tienes que esperar
  • Tienes que copiar el resultado
  • No se puede automatizar

✅ Con flag -p

  • Ejecuta directamente
  • La instrucción va en el comando
  • Devuelve resultado y sale
  • Se puede encadenar con otros comandos
  • Se puede automatizar en n8n
🔗
Conexión con tu ecosistema: Cuando conectes Claude Code a n8n, usarás -p en casi todos los nodos. n8n le pasa una instrucción, Claude Code la ejecuta y devuelve el resultado para el siguiente paso del workflow (flujo de trabajo automatizado).

🧬 Flag --model

Elegir el cerebro correcto para cada tarea

--model -m Gestión de recursos

Qué hace: Selecciona qué modelo de IA usar para la sesión. Cada modelo tiene diferente potencia, velocidad y coste. Por defecto usas Sonnet 4.6 — el equilibrado.

ModeloAliasPara qué usarloVelocidad
Claude Sonnet 4.6sonnetUso diario — equilibrio entre potencia y velocidad. Tu modelo actual⚡⚡⚡
Claude Opus 4.6opusTareas muy complejas — análisis profundo, estrategia, código complejo⚡
Claude Haiku 4.5haikuTareas simples y repetitivas — el más rápido y económico⚡⚡⚡⚡
# Cambiar modelo en el arranque: claude --model opus # Usar Opus para tareas complejas claude --model haiku # Usar Haiku para tareas simples claude --model sonnet # Volver a Sonnet (por defecto) # Cambiar modelo dentro del chat (sin cerrar): /model # Muestra el modelo actual /model opus # Cambia a Opus en la sesión activa
⚠️
Consejo de uso: Para el 90% de tus tareas diarias en MarketingMo, Sonnet 4.6 es suficiente y más rápido. Usa Opus solo cuando necesites análisis estratégico profundo o tareas que requieran razonamiento complejo.

🧠 Flag -s (--system-prompt)

El flag que define la identidad y el rol de Claude Code

-s --system-prompt Clave para agentes

Qué hace: Le da a Claude Code un rol, personalidad e instrucciones base antes de que empiece a trabajar. Es como el briefing inicial que le das a un empleado nuevo. Define quién es y cómo debe comportarse.

¿Cuándo usarlo? Siempre que necesites que Claude Code actúe como un especialista específico. Es la base de todos tus agentes — B.A.C., A.D.M. y A.C.I. tienen cada uno su propio system prompt.
🏢
Analogía para entenderlo: Imagina que tienes una agencia de marketing. Contratas a tres empleados: uno es especialista en contenido, otro en métricas y otro en auditorías de clientes. Antes de empezar les das a cada uno un manual de instrucciones. Ese manual es el system prompt.

La diferencia en la práctica

❌ Sin system prompt

  • Responde como asistente genérico
  • No sabe que eres de España
  • No conoce tu sector
  • Respuestas genéricas
  • No sigue tus convenciones

✅ Con system prompt

  • Actúa como experto específico
  • Sabe que es para España
  • Conoce tu sector y clientes
  • Respuestas especializadas
  • Sigue tus reglas y estilo

Ejemplos para MarketingMo

# System prompt para el Agente B.A.C.: claude -p -s "Eres el Agente B.A.C. de MarketingMo, especialista en marketing digital para negocios locales en España. Tu sistema es Briefing·Acción·Contenido. Siempre respondes en español, eres directo y orientado a resultados." "Crea el brief del cliente Eli Nails" # System prompt para análisis de métricas: claude -p -s "Eres el Agente A.D.M. de MarketingMo, experto en análisis de métricas de redes sociales. Analizas datos de Metricool y generas informes estructurados con benchmarks por plan de servicio." "Analiza el archivo metricas-noviembre.csv"
✅
Tu aplicación directa: Cada agente de tu ecosistema (B.A.C., A.D.M., A.C.I.) tiene su propio system prompt guardado en un archivo. Claude Code lo lee y sabe exactamente cómo comportarse para cada tarea.
⚠️
Importante: El flag -s reemplaza el system prompt por defecto de Claude Code. Si usas --append-system-prompt en cambio, añade tus instrucciones al prompt base sin reemplazarlo. Para la mayoría de tus casos usa -s.

🔄 Flag -c (--continue)

Retomar el trabajo donde lo dejaste

-c --continue Productividad diaria

Qué hace: Abre Claude Code retomando automáticamente la última conversación de esa carpeta. No empieza desde cero — recuerda todo el contexto de la sesión anterior.

¿Cuándo usarlo? Cuando cierras el ordenador y al día siguiente quieres continuar exactamente donde lo dejaste, con todo el contexto del proyecto activo.
# Arranque normal (desde cero): claude # Continuar la última sesión: claude -c # Continuar una sesión específica por ID: claude -r af77c5b5-31c2-437e-9b27-08194587a5c1 # El ID lo ves al cerrar Claude Code: "Resume this session with: claude --resume [id]"
✅
Consejo práctico: Cuando cierres Claude Code, guarda el ID de sesión que aparece al fondo. Así puedes retomar exactamente ese trabajo aunque hayas abierto otras sesiones en medio.

📋 Más flags útiles

Referencia completa de los flags que usarás en tu trabajo

FlagForma cortaPara qué sirveEjemplo
--print -p Modo no interactivo — ejecuta y sale claude -p "tarea"
--model -m Selecciona el modelo (sonnet/opus/haiku) claude --model opus
--system-prompt -s Define el rol y comportamiento base claude -p -s "rol" "tarea"
--continue -c Continúa la última conversación claude -c
--resume -r Retoma una sesión por su ID claude -r [id]
--max-turns — Limita el número de turnos de conversación claude -p --max-turns 5 "tarea"
--output-format — Formato de salida: text, json, stream-json claude -p --output-format json "tarea"
--verbose — Muestra todo el proceso detallado claude --verbose
--version -v Muestra la versión instalada claude --version
--add-dir — Añade otra carpeta al contexto de trabajo claude --add-dir ../clientes
❌
Flag peligroso — conocerlo para evitarlo: --dangerously-skip-permissions omite todos los avisos de seguridad y ejecuta sin pedir confirmación. NUNCA lo uses en tu ordenador personal. Solo para servidores aislados y entornos de prueba controlados.

⌨️ Atajos de teclado esenciales

Los que usarás todos los días dentro de Claude Code

!
Ejecutar comando del sistema. Escribe ! seguido de cualquier comando de terminal sin salir de Claude Code.

Ejemplo: ! mkdir nueva-carpeta
@
Referenciar un archivo. Le dices a Claude Code que trabaje con un archivo específico de tu proyecto.

Ejemplo: @clientes/brief-elnails.md resume esto
&
Tarea en segundo plano. Ejecuta una tarea sin bloquear el chat — puedes seguir escribiendo mientras trabaja.

Ejemplo: & analiza todos los archivos de la carpeta
Ctrl + Shift + -
Deshacer el último cambio. Si Claude Code modificó un archivo y no te gustó, esto revierte el cambio. Tu red de seguridad.
Ctrl + O
Ver output detallado. Expande los detalles de lo que está haciendo Claude Code. Útil para ver qué archivos leyó.
Ctrl + C
Interrumpir una tarea. Para Claude Code en seco si está haciendo algo que no querías. Siempre disponible como emergencia.
Esc Esc
Limpiar el input. Si escribiste algo mal y quieres borrar todo lo que escribiste sin ejecutarlo.
Ctrl + G
Abrir editor externo. Abre tu editor de texto configurado (VS Code) para escribir prompts largos con más comodidad.

🚫 Qué NO hacer con los Flags

Errores comunes de principiantes con los flags del CLI

❌
NUNCA uses --dangerously-skip-permissions en tu ordenador. Este flag desactiva todos los avisos de seguridad. Claude Code puede modificar o eliminar archivos sin preguntarte. Solo para entornos Docker o servidores de prueba aislados.
❌
NUNCA pongas contraseñas o API keys en el system prompt (-s). El system prompt se envía a los servidores de Anthropic con cada petición. Usa variables de entorno o archivos .env para credenciales.
❌
NUNCA uses el flag -p con tareas que requieren confirmación de archivos importantes. El modo no interactivo ejecuta sin preguntar. Para archivos de clientes en producción, usa el modo interactivo normal para revisar antes de confirmar.
⚠️
Cuidado con los system prompts muy largos en el flag -s. Si el system prompt es muy extenso, es mejor guardarlo en un archivo y usar --system-prompt-file ./mi-prompt.txt en lugar de escribirlo todo en el comando.
⚠️
El flag -s reemplaza el system prompt por defecto. Usarlo mal puede hacer que Claude Code pierda sus capacidades base. Si quieres añadir instrucciones sin borrar las originales, usa --append-system-prompt en cambio.
