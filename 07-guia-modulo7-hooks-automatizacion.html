🪝 Qué es un Hook

El concepto fundamental antes de entrar en la técnica

💡
Definición simple: Un Hook es una acción automática que se configura una sola vez y se dispara sola cada vez que ocurre un evento específico en Claude Code. No necesitas escribir nada, no necesitas recordarlo — simplemente ocurre en segundo plano mientras tú trabajas.
🎯
La analogía perfecta: Es exactamente como las notificaciones automáticas de tu teléfono. Tú no las activas manualmente cada vez — las configuras una vez y se disparan solas cuando pasa algo concreto. Recibir un WhatsApp → suena una notificación. Modificar un archivo de cliente → se registra en el log. Mismo concepto.

Hooks vs lo que ya sabes

Slash commandsTú los ejecutas manualmenteTareas específicas que tú decides cuándo hacer
Flags CLITú los configuras al arrancarModificar el comportamiento de una sesión concreta

Hooks Este móduloSe disparan solos al ocurrir un eventoAcciones automáticas en respuesta a lo que hace Claude Code

⚡ Los 8 eventos disponibles

Cada evento es un momento específico en el ciclo de trabajo de Claude Code

EventoCuándo se disparaUso típicoEstado
PostToolUse Después de que Claude Code usa una herramienta (Write, Edit, Bash...) Registrar cambios, validar archivos, notificar modificaciones Tienes uno ✓
PreToolUse Antes de que Claude Code use una herramienta Validar o bloquear operaciones antes de que ocurran Disponible
Stop Cuando Claude Code termina de responder Notificaciones, resúmenes automáticos, cierre de logs Tienes uno ✓
SessionStart Al arrancar una nueva sesión Mostrar recordatorios, cargar contexto adicional Disponible
SessionEnd Al cerrar Claude Code con /exit Generar resumen de la sesión, enviar logs a Notion Disponible
Notification Cuando Claude Code quiere comunicarte algo Redirigir notificaciones al sistema operativo Disponible
PreCompact Antes de comprimir el contexto con /compact Guardar un snapshot antes de comprimir Disponible
PostCompact Después de comprimir el contexto Notificar que el contexto fue comprimido Disponible
⚠️
Importante sobre PostToolUseFailure: Existe también el evento PostToolUseFailure que se dispara cuando una herramienta falla. Útil para registrar errores automáticamente en un log separado.

🏗️ Estructura técnica de un Hook

Cómo se configura en el settings.json — línea por línea explicada

Los hooks se configuran en el archivo settings.json dentro de la clave "hooks". Cada hook tiene tres partes esenciales: el evento, el matcher y el comando.

{
  "hooks": {
    "PostToolUse": [    ← El EVENTO que lo dispara
      {
        "matcher": "Write|Edit"   ← Qué herramienta lo activa
        "hooks": [
          {
            "type": "command"       ← Tipo: siempre "command"
            "command": "powershell ..." ← El comando a ejecutar
            "statusMessage": "Registrando..." ← Texto visible en pantalla
          }
        ]
      }
    ]
  }
}

El Matcher — qué herramienta activa el hook

MatcherQué activaEjemplo
"Write"Solo cuando escribe archivos nuevosCrear brief.md, informe-adm.md
"Edit"Solo cuando edita archivos existentesAñadir líneas a un brief ya creado
"Write|Edit"Cualquier modificación de archivosTu hook de auditoría actual
"Bash"Cuando ejecuta comandos de terminalCada vez que corre un script
"*"Cualquier herramienta sin excepciónLogging total de todas las acciones
💡
El operador | significa "O" — "Write|Edit" se dispara si usa Write O si usa Edit. Puedes combinar tantas herramientas como necesites separándolas con |.

📝 Hook 1 — Auditoría automática de clientes

El que creaste hoy — registra cada archivo de cliente modificado

📝
PostToolUse — registrar-edicion
Evento: PostToolUse · Matcher: Write|Edit · Script: .ps1
✅ Activo

Después de cada operación Write o Edit en cualquier archivo, el hook verifica si la ruta contiene clientes/. Si es así, escribe una línea en log.txt con la fecha, hora exacta y la ruta completa del archivo modificado.

🎯 Por qué es útil para MarketingMo: Tienes 12 clientes con múltiples archivos. Este hook crea un historial automático de todo lo que se toca — sin que tengas que recordar nada ni hacer nada manualmente.

El script PowerShell que lo hace funcionar

C:\Users\elias\claudecode-practicas\.claude\hooks\registrar-edicion.ps1
# Contenido del archivo registrar-edicion.ps1 $json = $input | Out-String try { $obj = $json | ConvertFrom-Json $f = $obj.tool_input.file_path if ($f -like "*clientes*") { $linea = "$(Get-Date -Format 'yyyy-MM-dd HH:mm:ss') | $f" Add-Content -Path "C:/Users/elias/claudecode-practicas/log.txt" -Value $linea } } catch {}

Qué hace línea por línea

LíneaQué hace

$obj = $json | ConvertFrom-JsonConvierte el texto JSON en un objeto de PowerShell

📄 Por qué usamos script .ps1 en Windows

La lección técnica más importante de este módulo para Windows

⚠️
El problema con hooks inline en Windows: Los hooks de Claude Code están diseñados para Linux/macOS donde los comandos Bash funcionan nativamente. En Windows, intentar escribir todo el comando inline genera errores de sintaxis. La solución correcta es usar un script externo .ps1.
MétodoEn Linux/macOSEn Windows
Comando inline✅ Funciona perfectamente❌ Error de sintaxis — comillas, pipes
Script externo .ps1✅ Funciona✅ Funciona perfectamente
Script externo .sh✅ Funciona⚠️ Requiere Git Bash configurado

Regla de oro para Windows

✅
Siempre que el hook necesite lógica compleja en Windows — usa un archivo .ps1 externo. El comando del hook simplemente llama al script: powershell -ExecutionPolicy Bypass -File C:/ruta/al/script.ps1. El script hace todo el trabajo pesado. Más limpio, más fácil de mantener, sin errores de sintaxis.

💡 Ideas de hooks futuros para MarketingMo

Automatizaciones que puedes añadir cuando las necesites

SessionEnd
Resumen diario de trabajo
Al cerrar Claude Code, genera automáticamente un resumen de todos los archivos tocados en esa sesión y lo guarda en un archivo diario.
Actívalo cuando: trabajes con muchos clientes en una sesión
PostToolUse
Backup automático
Cada vez que Claude Code modifica un archivo importante, hace una copia de seguridad automática con timestamp en una carpeta backups/.
Actívalo cuando: manejes briefs con información crítica de clientes
SessionStart
Recordatorio de tareas pendientes
Al arrancar Claude Code, muestra automáticamente los clientes que tienen informes pendientes este mes comparando con el log.txt.
Actívalo cuando: gestiones muchos clientes con fechas de entrega
PreToolUse
Validador de archivos protegidos
Antes de que Claude Code modifique cualquier archivo, verifica que no esté en una lista de archivos protegidos y bloquea la operación si lo está.
Actívalo cuando: tengas contratos o documentos legales en la carpeta
Stop
Contador de tokens por cliente
Al terminar cada respuesta, registra el coste estimado en tokens y lo acumula por cliente en un archivo de costes mensuales.
Actívalo cuando: quieras controlar el coste de Claude Code por cliente
PostToolUse
Envío a Notion al crear informe
Cada vez que se crea o actualiza un informe-adm.md, el hook lo envía automáticamente a la base de datos de informes en Notion.
Actívalo en: Módulo 8 cuando conectemos Notion completamente
💡
Regla de oro para hooks: Si te encuentras haciendo la misma acción manual después de que Claude Code termina de trabajar (guardar un log, hacer backup, enviar a Notion), esa acción debería ser un hook automático. Los hooks son para eliminar el trabajo repetitivo post-proceso.

🚫 Qué NO hacer con los Hooks

Errores comunes que pueden romper los hooks o causar problemas

❌
NUNCA uses comandos inline complejos en Windows. Los pipes, comillas anidadas y caracteres especiales en comandos inline dentro del JSON generan errores de sintaxis en Windows. Siempre usa un script .ps1 externo para lógica compleja.
❌
NUNCA olvides reiniciar Claude Code después de añadir un hook nuevo. Los hooks se leen al arrancar la sesión. Si añades un hook mientras Claude Code está abierto, no lo detectará hasta que hagas /exit y vuelvas a abrir. El único que funciona sin reiniciar es el evento Stop.
❌
NUNCA pongas hooks que hagan operaciones destructivas sin confirmación. Un hook se dispara automáticamente sin preguntarte. Si un hook borra archivos o los modifica de forma irreversible, no hay forma de detenerlo una vez disparado. Los hooks son para operaciones seguras y reversibles.
⚠️
Cuidado con hooks que generan bucles. Si un hook escribe en un archivo y ese archivo está dentro del matcher del hook, puede dispararse a sí mismo indefinidamente. Por ejemplo: un hook en Write que escribe en log.txt — si log.txt está dentro del matcher, el hook se dispararía de nuevo al escribir en log.txt.
⚠️
Los hooks con errores no bloquean el trabajo de Claude Code. Si tu script .ps1 tiene un error, el hook falla silenciosamente pero Claude Code sigue trabajando. Verás PostToolUse:Edit hook error en la pantalla. Eso es una señal de que el script necesita corrección.
